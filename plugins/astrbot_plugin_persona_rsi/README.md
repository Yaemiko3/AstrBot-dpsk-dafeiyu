# 大肥鱼自我迭代 · 技术说明

少折腾 prompt，让大肥鱼从真实聊天中学习更自然的表达。同一提案可以修改人格习惯、消息运行参数或行为代码，经过功能检查和聊天回放后自动生效，统一保存版本并回退。

[项目介绍](../../README.md) · [接入指南](../../docs/astrbot-setup.md)

## 0.4.0 版怎么工作

1. 主要入口是 LivingMemory 采集的真人之间的原始聊天，目标人格自己的对话作为辅助反馈。群聊入口导入最近 **7 天**历史，之后每分钟增量同步；不把记忆总结当真人样本。
2. 群友交流在所有已接入的群中合计达到 **5 个完整片段**即可学习，优先于直接对话；每批取合并后最近16个片段。不要求机器人参与、犯错或获得评价。两条入口共用 **6 小时**间隔；连续两轮真人学习后，若直接对话已满 **40 轮**，安排一轮辅助反馈；没有新的真人批次时也可使用已满额的直接对话。
3. 真人素材由专门的表达观察员提炼1～2条“适用情境→表达动作→停止条件”，程序将观察转换为候选习惯，沿用当前参数和代码，再进入统一评估。观察员不接收基础人格长文或行为参数，避免先找机器人错误；审查阶段仍核对完整人格和核心。每条习惯引用至少三名群友、三个独立场合的原话，可全来自同一群，同群场合至少相隔五分钟。直接对话的辅助提案仍可修改习惯、参数或代码，引用2～8轮。两个入口都将最后两个轮次或片段完整留出。
4. 生成独立候选目录，包含完整人格、参数和 `behavior.py`。先执行行为接口检查，再独立调用模型审查变更与证据。证据校验或审核退回后，带着具体意见在同一批训练素材上修正一次，重新完整校验与审核；群聊决定不修改时，也复核一次旁观学习依据。每轮总共最多两次提案，不因修正提前接触留出样本，仍可选择不修改。可另配审查模型，留空复用当前模型。
5. 旧版本和候选版本分别运行消息行为模块，再生成 **7 个固定场景 + 2 个留出输入**的回复。固定场景包含普通抱怨、接梗后收尾和无必要的总结追问，同时保留认真求助，避免只奖励短回答。评估同时比较上下文选择、合并、延迟和回复效果；群聊真人回复和场景评判要点仅在评估时提供。X/Y 位置随机，至少两项更好、平均提升至少0.5/5，且无核心冲突或单项退步才采用。
6. 人格通过 `PersonaManager.update_persona` 刷新；参数和代码随数据库中的统一版本切换，后续请求直接读取新版。每次请求固定使用一个版本。回退同时恢复三者；新行为出现运行错误时，本次请求使用默认行为，后台恢复上一版本并暂停迭代。

## 能自行修改什么

| 目标 | 当前可修改内容 | 生效位置 |
| --- | --- | --- |
| 人格 | 最多六条、700字表达习惯，每轮最多改两条 | AstrBot 真实人格 |
| 参数 | 等待、上下文条数/时效/字数、发送延迟，每轮最多改三项 | 请求与发送钩子 |
| 代码 | `behavior.py` 的上下文选择、连续补充合并和节奏算法 | 实际执行的行为模块 |

可修改参数：`coalesce_window_ms`（0～3000毫秒）、`context_message_limit`（0～12条）、`context_max_age_seconds`（30～1800秒）、`context_char_budget`（0～6000字）、`send_delay_ms`（0～1500毫秒）。默认不额外等待、不补上下文，待 RSI 根据证据决定调整。

行为模块保留两个入口：`plan_request(messages, request, settings)` 返回等待时间、上下文消息ID和可合并的补充消息ID；`plan_response(text, settings)` 返回发送延迟。候选源代码在独立目录检查，采用后的代码在独立进程执行，单次限时2秒、内存384MB。初始内置实现直接运行，避免给未修改的聊天增加进程启动开销。

这版代码执行器的范围是消息行为模块；AstrBot 核心、第三方插件和评估器保持由项目代码维护。新增其他接口时，可以继续接入同一份提案、测试、版本和回退流程。

收到消息时先被动观察，不唤醒机器人。实际回复请求按版本选择上下文，同一人紧接着补充的文字可以一起回答；只有回复进入发送阶段后才将对应补充标为已处理。其他人的消息、命令和超龄上下文不能被合并。仍由 AstrBot 控制唤醒与主动发言。

群聊按时间间隔整理：空闲两分钟、持续超过五分钟或出现机器人回复时分段；仍在进行的片段等待结束。每段保留前16条消息，长串刷屏不会按条数拆成多个证据。时间分段可能混有话题，审查模型还会核对上下文是否真支持同一种习惯。

首要目标是学习可迁移的人类表达，不按群隔离人格，也不要求同一种习惯在多个群重复出现。群号仅用于理解上下文、核对独立场合和遵守已有采样白名单。适用条件由眼前的话题、情绪与关系决定；可以跨群使用抒情、接梗等方式，但不把某人的经历或某群的专有事实写成自己的经历。复读只是可能学到的行为，程序没有预设“必须学会复读”。本版更新接话方式，主动插话时机仍由现有 AstrBot 设置控制。

“不修改”是正常结果。证据不足、判断不通过或调用失败时不会强行生成升级。模型评估只是筛选依据，真实聊天仍可能退步，可随时回退。

角色核心约束集中维护在 [policy.py](policy.py)，每轮评估都会核对。个人的专属偏好继续由 LivingMemory 保存。

## 安装到本机

从仓库根目录运行：

```powershell
python scripts/deploy_persona_rsi.py --core "<AstrBot核心目录>" --enable --provider "<模型提供商ID>"
```

重载插件或重启 AstrBot，在 `persona_id` 中填写实际使用的目标人格 ID。`allowed_sessions` 可指定采样的会话 UMO；留空采样该人格的会话。群聊还会核对当前白名单、会话开关和插件开关。首次启动先保存基础版本并导入历史，达到条件后后台评估。

`group_learning_enabled` 开关群聊学习；`group_history_days` 设置1～30天的历史窗口；`excluded_bot_ids` 填其他机器人的账号。自己的回复、已标记的机器人消息自动排除；未知机器人仍需用账号排除。群聊来源为 LivingMemory 的 `conversations.db`，只读访问，需开启 LivingMemory 全量群聊采集。来源缺失时直接对话学习仍可工作。

目前仅适配并在 AstrBot **4.29.3** 接口上验证，声明范围为 `>=4.29.3,<5`。只依赖 Python 标准库与 AstrBot SDK。

## 管理指令

以下均为 AstrBot 管理员指令：

| 指令 | 作用 |
| --- | --- |
| `/prsi status` | 当前版本、直接对话与群聊采样进度、最近结果 |
| `/prsi habits` | 当前统一生效的表达习惯 |
| `/prsi runtime` | 当前统一版本、行为代码指纹与实际参数 |
| `/prsi history` | 最近提案与采用/拒绝结果 |
| `/prsi run` | 立即检查一次；仍需足够新对话，仍遵守暂停状态 |
| `/prsi pause` | 暂停迭代，仍采集对话 |
| `/prsi resume` | 恢复迭代 |
| `/prsi rollback` | 回退到当前版本的父版本，并暂停自动迭代 |
| `/prsi adopt` | 将手工修改后的人格接纳为新基础；须先移除旧 RSI 标记段 |

每次回退本身也会形成新版本，因此连续回退会沿新版本的父关系切换；先用 history 查看。后台迭代不主动往群里发报告。

## 文件与人工编辑

插件代码在 `plugins/astrbot_plugin_persona_rsi/`，运行数据位于 AstrBot 的 `data/plugin_data/astrbot_plugin_persona_rsi/<人格ID哈希>/`：

- `persona_rsi.db`：原始对话、运行轨迹、完整版本快照、评估报告、当前状态。
- `active_persona.md`：当前生效人格的导出副本。
- `active_runtime.json`、`active_behavior.py`：当前生效参数与代码的导出副本。
- `candidates/<提案ID>/`：候选文件、提案和评估报告。

运行时以数据库中的活动版本为准，导出文件用于查看和分享。升级会备份旧插件、配置和版本数据库；0.3 会把历史证据交给统一流程重新评估一次。

0.4 首次加载会让近期真人素材按表达学习目标重新评估一次，保留活动版本、历史报告、直接对话游标和暂停状态。`report.observation` 保存“情境、回应、收尾、原话引用”，`report.proposal` 保存转换后的统一提案。

自动迭代更新 AstrBot 内的人格及上述导出文件。仓库 `prompts/dafeiyu.md` 和 `personas/dafeiyu_custom.json` 作为人工维护的基础版，不会被后台自动覆盖；要分享学习结果，从 `active_persona.md` 取出所需习惯再整理。

手工修改 AstrBot 人格后，插件发现与已知版本不一致会停止覆盖，状态显示 `external_edit`。确认手工版本后使用 `/prsi adopt` 建立新基础。更新失败或重启中断会比对正在应用的版本和真实人格，避免把未写入的版本记作生效。

一次完整评估通常 **21 次模型调用**：提案1、审查1、九组双回复18、比较1；触发修正时最多23次，被前序检查拒绝会提前结束。单次后台轮次最长720秒，每组旧版与候选回复并发生成。修正使用同一轮机会，不额外等待6小时；本轮结束后恢复正常间隔。首次升级到修正流程会解除一次冷却以处理尚未使用的素材，保留已消费的样本游标、活动版本和暂停状态。代码功能检查与回放不发送群消息。原始样本保存在本地运行目录，不纳入 Git；选中的样本文本会发送给已配置的模型用于分析。

官方 DeepSeek 后台调用使用已配置的客户端，单独关闭思考模式并对结构化任务启用 JSON 输出，避免思考耗尽输出预算；不改日常聊天模型配置。其他提供商通过 AstrBot 统一模型接口调用。该版本 AstrBot 的 OpenAI 适配器未转发部分单次调用参数，因此后台对官方 DeepSeek 做了专项适配。

可先在隔离状态中使用最近聊天预演（会调用模型，但不改真实人格）：

```powershell
python scripts/preview_persona_rsi.py --core "<AstrBot核心目录>" --provider "<模型提供商ID>" --persona "<目标人格ID>" --turns 40

# 群体学习预演，可重复 --group-session 对照多个群
python scripts/preview_persona_rsi.py --core "<AstrBot核心目录>" --provider "<模型提供商ID>" --persona "<目标人格ID>" --group-session "<会话UMO>"
```

预演从 LivingMemory 配对相邻文字消息，仅作启动检查；正式运行采用本插件在同一事件中捕获的请求/回复，配对更准确。

## 验证与已知限制

```powershell
python -m unittest discover -s tests -v
```

测试覆盖人格、参数、代码单独及组合生效，统一回退、中断恢复、执行超时、群体证据、真实钩子中的合并和延迟。旧对话没有运行轨迹时只能回放文字，新增对话会记录消息时序与行为决策。回放不完整复现图像与工具结果；QQ 发送阶段钩子也不是远端送达确认。模型评分用于筛选，实际聊天反馈继续进入下一轮学习。

接口依据：[AstrBot 人格管理与模型调用](https://docs.astrbot.app/dev/star/guides/ai.html)、[消息事件钩子](https://docs.astrbot.app/dev/star/guides/listen-message-event.html)。
